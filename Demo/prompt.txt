Moving away from relying solely on Cloud APIs, the system now adopts an Audio Template Caching approach. Cloud API usage is now strictly restricted to general conversations (Chit-chat) that have been filtered and verified as containing absolutely no personally identifiable information (Zero-PII).
Regarding conversation logic and urgency assessment, the system limits the scope of small talk by listening and immediately steering the patient back to the symptom screening process. It also applies a 3-Strike Rule: if the patient consistently answers off-topic or shows signs of continuous confusion, the system converts these conversational errors into clinical indicators of Altered Mental Status according to ESI Level 2 criteria. This automatically triggers an alert to the nurses on the dashboard.
To avoid over-engineering the selection of audio tools, the system operates in two main modes:

On-Topic Mode (Direct Answers):
When the user stays on topic, we primarily use Fast Whisper for STT (Speech-to-Text). Because raw voice-to-text conversion often contains personal data, sending it to external APIs would compromise privacy. The transcribed text is sent to the LLM, which then outputs a filtered context (guaranteed to be clean and free of personal data) to the TTS (Text-to-Speech) pipeline. Because the user is answering directly, the system simply plays local Audio Template Caching (.mp3) files rather than dynamically generating speech via Piper or gTTS, significantly reducing computational overhead.
Off-Topic Mode (Irrelevant Answers):
If the user talks off-topic or gives mismatched answers (e.g., answering "I already ate" when asked for their name), the system still processes the audio safely since Fast Whisper is used locally for STT in all cases. The text is then sent to the LLM. The LLM is prompted to engage in brief small talk to acknowledge the user before immediately pivoting back to the screening topic. Because we cannot pre-record audio templates for unpredictable answers, the system dynamically converts this text to speech on the fly to maintain the system's "smart" feel. In this mode, we use gTTS instead of Piper to keep the processing load lightweight.
